Install and configure ​

cninfo-mcp is published on npm as @youhaozhao/cninfo-mcp. It starts with npx and speaks MCP over stdio, so it works with any client that supports local MCP servers.

Prerequisite: Node.js 22.13+ ​

Node.js 22.13 or newer is the only requirement. No Python and nothing else to install.

bash
node -v   # should print v22.13.0 or higher

If your version is older, install the current LTS release from nodejs.org or upgrade with a version manager such as nvm or fnm.

Install by client ​

Claude Code ​

bash
claude mcp add cninfo -- npx -y @youhaozhao/cninfo-mcp

By default the server is added for the current project only. To use it in every project, add --scope user:

bash
claude mcp add --scope user cninfo -- npx -y @youhaozhao/cninfo-mcp

Run /mcp inside Claude Code to see the connection status and the list of tools.

Native Windows (not WSL)

On native Windows, local MCP servers started with npx need a cmd /c wrapper:

bash
claude mcp add cninfo -- cmd /c npx -y @youhaozhao/cninfo-mcp

Claude Desktop ​

Open Settings → Developer → Edit Config, add the block below, and restart the app. The config file is at:

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json
json
{
  "mcpServers": {
    "cninfo": {
      "command": "npx",
      "args": ["-y", "@youhaozhao/cninfo-mcp"]
    }
  }
}

Cursor ​

Add this to ~/.cursor/mcp.json (global) or to .cursor/mcp.json in a project:

json
{
  "mcpServers": {
    "cninfo": {
      "command": "npx",
      "args": ["-y", "@youhaozhao/cninfo-mcp"]
    }
  }
}

VS Code ​

From the command line:

bash
code --add-mcp '{"name":"cninfo","command":"npx","args":["-y","@youhaozhao/cninfo-mcp"]}'

Or in .vscode/mcp.json in your workspace (note that VS Code uses the key servers):

json
{
  "servers": {
    "cninfo": {
      "command": "npx",
      "args": ["-y", "@youhaozhao/cninfo-mcp"]
    }
  }
}
Add to VS Code

Codex CLI ​

bash
codex mcp add cninfo -- npx -y @youhaozhao/cninfo-mcp

This is equivalent to adding the following to ~/.codex/config.toml:

toml
[mcp_servers.cninfo]
command = "npx"
args = ["-y", "@youhaozhao/cninfo-mcp"]

Gemini CLI ​

Add the mcpServers block from the generic configuration to ~/.gemini/settings.json, or to .gemini/settings.json in a project.

OpenClaw ​

bash
openclaw mcp add cninfo --command npx --arg -y --arg @youhaozhao/cninfo-mcp
openclaw mcp doctor cninfo --probe

The OpenClaw documentation says the local Gateway has to be stopped before saved servers are changed, so stop it first and start it again afterwards.

Other clients (generic configuration) ​

Cline, Windsurf, Zed, Cherry Studio and other clients keep their configuration in different places, but the content is the same: the command npx with the arguments -y and the package name.

json
{
  "mcpServers": {
    "cninfo": {
      "command": "npx",
      "args": ["-y", "@youhaozhao/cninfo-mcp"]
    }
  }
}

Check that it works ​

To confirm that your machine can reach CNINFO, run the online self-test. It queries annual reports on the Shanghai, Shenzhen and Beijing exchanges, calls the financial data endpoint once and reads one document:

bash
npx -y @youhaozhao/cninfo-mcp probe
txt
[OK  ] 年报查询 沪市 SSE: 600519=27
[OK  ] 年报查询 深市 SZSE: 000001=25
[OK  ] 年报查询 北交所 BSE: 920185=5
[OK  ] 财务数据 data20: 3 periods, 6 rows
[OK  ] 文档读取 static: 贵州茅台2026年第三季度报告: 12 pages, 11065 chars

全部探测通过。

The last line means that every probe passed. There is also an offline check that only verifies the installation itself (PDF text extraction):

bash
npx -y @youhaozhao/cninfo-mcp selftest

Then try a first question in your client:

Find the latest annual report of Kweichow Moutai (600519) and tell me how many pages it has and what the main sections are.

Configuration ​

Everything is set through environment variables, and all of them are optional.

VariablePurposeDefault
CNINFO_MCP_DOWNLOAD_DIRDownload root. The download tools can only write inside it~/Downloads/cninfo-mcp
CNINFO_MCP_CACHE_DIRCache for the securities list and for documents that were readcninfo-mcp in the platform cache directory
CNINFO_MCP_CACHE_MAX_MBDocument cache limit; least recently used files are evicted beyond it1024
CNINFO_MCP_CONCURRENCYSimultaneous requests to CNINFO (1 to 8)4

In a JSON configuration, use the env field:

json
{
  "mcpServers": {
    "cninfo": {
      "command": "npx",
      "args": ["-y", "@youhaozhao/cninfo-mcp"],
      "env": {
        "CNINFO_MCP_DOWNLOAD_DIR": "/Users/me/Research/filings"
      }
    }
  }
}

In Claude Code, use --env (options go before the server name):

bash
claude mcp add --env CNINFO_MCP_DOWNLOAD_DIR=/Users/me/Research/filings cninfo -- npx -y @youhaozhao/cninfo-mcp

The remaining options (request timeout, debug logging) are listed in the tools reference.

Do not raise the concurrency

CNINFO answers bursts of requests with HTTP 403 and blocks the IP address for a while. The server already rate-limits all upstream requests and backs off when throttled, so the default is the right setting.

Upgrade and uninstall ​

  • Check the version: npx -y @youhaozhao/cninfo-mcp --version
  • Upgrade: npx may keep using a version it has already cached. Write the package name as @youhaozhao/cninfo-mcp@latest in your configuration to run the latest release on every start.
  • Coming from 2.x or earlier: 3.0 is a breaking release with renamed tools and no Python dependency. The upgrade guide (in Chinese) lists the changes.
  • Uninstall: remove the cninfo entry from your client configuration (claude mcp remove cninfo in Claude Code). The download and cache folders can be deleted by hand.

Troubleshooting ​

The client reports that the server failed to connect ​

Check that node -v is at least 22.13. Desktop apps such as Claude Desktop do not always see the Node.js path configured in your shell; in that case set command to the absolute path of npx (which npx on macOS and Linux, where npx on Windows).

Queries fail with 403 or a rate-limit message ​

That is CNINFO throttling. The server pauses and retries automatically, and it usually recovers within a short while. Do not raise CNINFO_MCP_CONCURRENCY, and avoid running several clients against CNINFO at the same time.

A document comes back empty ​

Some older filings are scanned images with no text layer, so their content cannot be read as text. read_document says so in its result.

More answers are in the FAQ. To report a problem, open an issue on GitHub.
