性能与稳定性 ​

查询 ​

  • 按 orgId 精确查询：先用本地缓存的证券目录把代码解析成巨潮的 orgId，一条请求链即可查到一家公司在沪、深、北任一市场的公告，不必逐个交易所扫描后再过滤。同一发行人的多个代码（A+B 股、北交所新旧代码）会一并查询。
  • 并发翻页：上游每页最多 30 条。第一页返回总数后，其余分页并发抓取。

限速与重试 ​

  • 全局限速：所有上游请求共用一个并发上限（默认 4）和最小发起间隔，多个工具调用同时进行时也不会叠加。
  • 限流冷却：巨潮用 403 表达限流。遇到 403 / 429 时全局暂停一段时间再重试，而不是继续撞限流。
  • 自动重试：超时、网络错误、5xx、空响应、数据接口的内部失败（HTTP 200 但 resultMsg=fail）按指数退避加抖动重试；404 等确定性错误立即返回。

并发上限不建议调高：短时间内大量请求会让巨潮返回 403 并暂时封禁 IP。

缓存 ​

  • 证券目录：内存和磁盘各一份，12 小时更新一次；上游不可用时退回磁盘上的旧副本。
  • 查询结果：短时缓存，并合并同时发起的相同请求。不完整的结果不进缓存。
  • 文档：读过的文档及其逐页文本落盘缓存，再次读取或下载不需要重新抓取和解析。缓存超过上限时淘汰最久未使用的文件。

结果完整性与故障隔离 ​

  • 部分分页、部分数据集或部分文件失败时，已取得的内容照常返回，并用 complete: false 明确标出，不会把残缺结果当作完整结果。
  • 单个文件下载失败、单个数据集失败、单页 PDF 解析失败都不会拖垮整次调用。
  • 下载和缓存都是先写临时文件再原子改名；限流时返回的 HTML 错误页不会被当作 PDF 保存。
  • 客户端退出后服务器随即结束，不留下孤儿进程。

监控 ​

仓库的定时工作流每天运行一次 cninfo-mcp probe，实际探测沪、深、北交所的年报查询、财务数据接口和文档读取，异常时自动开 issue。
